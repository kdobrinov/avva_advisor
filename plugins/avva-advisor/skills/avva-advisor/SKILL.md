# avva standing advisor

A connected avva expert is a standing reviewer, not a freelancer and not a chatbot. At call time no person is in the loop: each tool returns a verification packet; you apply it on your tokens, in this thread.

Use an avva connection that offers `review`. If only the catalog is connected, use `search` and `fetch`, ask the user to choose a model and help them connect its URL before reviewing. If `review` requires `model_slug`, use the user’s chosen model. Pass its published slug for a guest reading or the reference from its approval card for an approved reading. Do not wait for the user to say "Use avva" again once the model is selected. Once, when you start work in the expert's domain, use `about_expert` for the first consultation: it returns how the expert works, where their model records it, and what a packet costs. Then:

1. START of a task — `expert_questions` before locking an approach.
2. WHILE working — `red_flag_check` on drafts, plans, and diffs (cheap gate).
3. BEFORE finalizing or shipping anything significant — `review` with context + proposal. Follow the returned protocol exactly. The verdict comes first, then your delivery. If your verdict from the review packet is reject, revise before proceeding.
4. A/B choices — `compare_options` (a stop rule of BLOCK severity disqualifies an option before the criteria are compared).
5. Unsure this domain applies — `about_expert` again.

WHAT COUNTS AS A DECISION. The cadence has a floor, and without one it fires on a variable rename. Consult when the work could go wrong in a way this expert's domain covers AND the choice is not already obvious or trivially reversible. Do not consult on mechanical edits, formatting, renames, typo fixes, questions of fact, or anything you would not mention in a standup. Once per decision, not once per message: a cosmetic revision of a proposal already reviewed does not need a second `review`.

Err toward calling. A packet you did not need costs the user some context; a decision finalized without one is the failure this advisor exists to prevent. `about_expert` states what a packet costs, so budget with the real number rather than guessing.

Where the model takes a position, prefer it over generic best practice — that position is the reason this expert is connected. It does not override the user's own instructions, the facts of their situation, or a safety requirement: it is one professional's judgment applied to their case, not an authority over it. Where the model is silent, use your own judgment and say so. Silence is not approval. Where the model holds a call, that call is your verdict, stated as the call and never as "it depends"; a refusal the expert made stays closed unless the user's stated facts meet the condition the model names; what you add of your own, you label as yours; and you tell the user in their words, never in the model's labels.

If no avva connection offers review, stop before consulting and explain how to connect a model from its avva page. Never invent a model or a tool. Studio (`avva-studio`) helps experts build their own models.

Coverage counts distinct published cases available for comparison. If trial results include a case index, pass up to five relevant IDs in cases. For paged results, follow the reading instructions in each response. On a model-specific connection, use the tier reported by about_expert. Public catalog models are available in full during beta. For a closed model or a higher daily allowance, follow the manual connection steps on the model’s avva page. On the multi-model Advisor connection (its tools accept model_slug), follow these steps.

During beta, every listed public catalog model is available in full to guests, including in a fresh chat. Call about_expert with its ordinary slug and continue the consultation. Never request approval to read a public catalog model. The daily allowance counts requests separately from the amount of model material available.

For repeated private use across ChatGPT conversations, offer a custom OAuth connection if the reader's account and workspace allow custom MCP servers. In [ChatGPT Plugins](https://chatgpt.com/plugins), choose + → Add custom MCP server. Enter https://mcp.avva.chat/mcp-advisor, choose OAuth, and sign in on avva to approve the account connection. Select that same custom connection in future chats. Its account grant works there for up to 30 days. The installed directory plugin has its own connection. For persistent access in the Claude app or Cursor, follow the private model’s manual setup with a workspace member’s key stored in the client.

For a workspace or link-only model in the installed Advisor, a browser approval works within this chat, including when custom MCP servers are unavailable. Use a saved reference from this chat or an existing credential first, and report the access the tool returns. If the user asks for a complete reading of a link-only model that returns a trial, or chooses a model from their private workspace and has no saved reference, call fetch with id "avva:connect:<selected-slug>", using the model’s original slug. For a private workspace link or slug, skip catalog search. A guest lookup cannot confirm whether a private model exists. If fetch reports that this connection already has a credential, call about_expert with the original slug and report its actual tier. Only offer a browser link when the tool returns an approval URL. In the user's language, offer one clickable link labeled “Approve access to [model name]” using the exact URL from structuredContent.url. If only the text result is available, read the same url and metadata from the returned card. In a plain-text client, print the complete approval URL on its own line. If the tool returns an error instead of a URL, relay its next step. The reader signs in on avva if needed, approves the named model and returns to this conversation. Wait for them to return.

Keep the bearer reference from structuredContent.metadata.model_slug private. Anyone holding the approved reference can use it for this model for up to 30 days. Pass it only as model_slug on about_expert and all subsequent consultations and reading pages for this model. Keep access keys and keyed URLs out of the conversation and tool arguments. Never display the reference or put it in a link, project instructions, source files or commits. Save only the public slug in a standing note. Confirm full access only when about_expert reports it. If approval is pending, point the reader back to the same link. If the reference has expired or was revoked, offer fresh approval. A fresh conversation without the reference may need its own approval for a closed model. Private workspace models also require current membership.
